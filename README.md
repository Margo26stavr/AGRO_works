# Отчёт по полевым работам — мобильная версия

Живой отчёт из книги `ПланФакт2026.xlsm`. Агроном как и раньше заполняет лист
**«Общий свод 2026»**, руководитель открывает **одну ссылку** на телефоне и видит
план-факт по видам работ — за день, накопительно и по срокам, со срезами по
предприятиям и культурам.

Ссылка для руководителя:
`https://<ваш-логин>.github.io/<имя-репозитория>/`

---

## Что получается на выходе

| Файл | Что это | Где смотреть |
|---|---|---|
| `docs/index.html` | мобильный отчёт | ссылка выше |
| `docs/data.json` | данные отчёта | пересобирается автоматически |
| `docs/otchet.xlsx` | Excel-отчёт для руководства | кнопка **«Скачать Excel»** в отчёте |
| `docs/otchet-offline.html` | тот же отчёт одним файлом с вшитыми данными | переслать в Telegram/WhatsApp, работает без интернета |
| `reports/otchet_ГГГГ-ММ-ДД.xlsx` | архив отчётов по дням | папка `reports` в репозитории |

### Три вкладки в телефоне

- **Сводка** — виды работ карточками: процент, факт, план, остаток. Нажатие на
  карточку раскрывает разбивку по культурам и предприятиям с графиком выработки.
- **По дням** — гистограмма последних 3 недель; нажатие на столбик или карточку
  дня перестраивает список. Переключатель **«За день / Накопительно»**.
- **Сроки** — плановые и фактические сроки полосами на одной шкале, отметка
  «позже плана» и статус закрытия агросрока.

Срезы — предприятие и культура — чипами наверху, действуют на всех вкладках.
Состояние среза пишется в адрес страницы, поэтому конкретный разрез
(например, «Колос, горох овощной») можно просто переслать ссылкой.

### Excel-отчёт

Пять листов: **Сводка**, **По дням**, **Сроки**, **Данные**, **Выработка**.
Числа на первых трёх листах — формулы `SUMIF`/`SUMIFS` к листам-источникам,
поэтому отчёт пересчитывается сам, а не «замораживает» цифры на дату сборки.

## Как запустить у себя — один раз

1. Создать репозиторий на GitHub и загрузить в него содержимое этой папки.
2. **Settings → Pages → Source: GitHub Actions.**
3. **Settings → Actions → General → Workflow permissions: Read and write permissions**
   (нужно, чтобы бот складывал архив отчётов).
4. **Actions → «Сборка отчёта по полевым работам» → Run workflow.**
   Через минуту ссылка на Pages заработает — её и отдать руководителю.

## Как обновлять — каждый день

Агроном заполняет `ПланФакт2026.xlsm` как обычно, затем в репозитории:
**`data` → `Add file` → `Upload files`** → перетащить книгу → **Commit changes**.

Сборка запустится сама. Отчёт по ссылке обновится через 1–2 минуты.
Дополнительно сборка идёт по расписанию каждый день в 18:00 МСК.

> Если книга лежит в общей папке (OneDrive, Яндекс.Диск, сетевой диск) — вместо
> ручной загрузки поставьте на компьютер агронома задачу планировщика с
> `git add data/ && git commit && git push`, тогда обновление станет полностью
> автоматическим.

## Локальный запуск

```bash
pip install -r scripts/requirements.txt
python scripts/build_report.py --src "data/ПланФакт2026.xlsm" --out docs
python -m http.server -d docs 8000     # открыть http://localhost:8000
```

Отчёт на конкретную дату (например, чтобы поднять картину на конец недели):

```bash
python scripts/build_report.py --date 2026-05-24
```

## Как читается исходный лист

`scripts/parse_svod.py` разбирает «Общий свод 2026» по его текущей структуре:

| Что | Где |
|---|---|
| Даты сезона | строка 3, начиная со столбца `N` |
| Вид работ / подоперация | столбец `A` |
| Культура | столбец `B` |
| Предприятие | столбец `C` |
| Общий план, га | столбец `D` |
| Сроки план / факт | столбцы `J`–`M` |
| Выработка за день, га | столбцы `N` и правее |

Правила распознавания строк:

- `A` заполнен, `B` пуст, плана нет → **заголовок раздела** (`ВЕСЕННЕ-ПОЛЕВЫЕ РАБОТЫ`);
- `A` заполнен, `B` пуст, в `D` формула `СУММ` → **строка-итог вида работ**;
- `A` и `B` заполнены → строка данных с собственной подоперацией
  (`Селитра аммиачная`, `гербицидная`);
- `A` пуст, `B` заполнен → строка данных, вид работ наследуется у группы выше.

Блок погоды в строках 4–13 пропускается: разбор начинается после первого
заголовка раздела. Факт считается суммой дневных ячеек, а не берётся из столбца `E` —
так отчёт не зависит от того, пересчитались ли формулы в самой книге.

**Что стоит поправить в своде** — разбор это переживёт, но цифры станут чище:

- `Культивация№111` (строки 83–88) полностью дублирует `Культивация№1` —
  в сводном плане это лишние 970 га;
- разнописание культур: `Подсонечниик` / `Подсолнечник`,
  `Кукуруза (сладкая)` / `Кукуруза сладкая` / `Кукуруза супер.сладкая(полив)` —
  каждый вариант считается отдельным срезом в фильтре;
- в строках 61 и 79 нет ни культуры, ни плана — они выпадают из отчёта.

docs/index.html                   мобильный отчёт
.github/workflows/build-report.yml  автосборка и публикация
reports/                          архив Excel-отчётов по датам
